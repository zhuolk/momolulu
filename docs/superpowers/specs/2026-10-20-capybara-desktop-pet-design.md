## 1. 背景与目标

已采集 506 个唯一的「水豚噜噜」GIF（总计 329.24 MB），需要把它们变成一个常驻桌面的桌宠程序：既要有可爱的桌面形象，也要有实用的提醒与效率工具。

**目标（本次交付范围）**

1. 单只噜噜桌宠，运行在桌面最上层，可拖拽移动。
2. 双轨制视觉：能干净去背的素材 → 真透明桌宠；去背失败的素材 → 圆角贴纸卡片。
3. 行为状态机：待机、走动、睡觉、吃饭、喝水、开心、生气等状态由不同分类的 GIF 驱动。
4. 五个可独立开关的实用模块：番茄钟/专注计时、喝水+久坐提醒、12:00 与 18:30 吃饭提醒、整点报时、系统状态监控。
5. 系统集成：系统托盘、开机自启、鼠标穿透（双模式切换）、始终置顶、拖到屏幕边缘自动隐藏只露桔子。
6. 素材流水线：去背 + 优化压缩 + 缩略图接触表 + 人工分类，并支持后续增量素材（新一批 GIF）无缝替换/追加。
7. 交付形态：先可调试的脚本运行，再用 PyInstaller 打包为 Windows 可执行程序。

**成功标准**

- 双击 `main.py`（或打包后的 exe）后，桌面上出现噜噜，可拖动、可点，退出后无残留进程。
- 托盘菜单可切换穿透/交互模式、逐个开关五个模块、开关开机自启。
- 拖到屏幕左右边缘松手后自动隐藏，只露出桔子；鼠标移到桔子上滑出恢复。
- 12:00 / 18:30 到点播放吃饭类 GIF 并弹出气泡。
- 追加新素材时，只需把新 GIF 丢进 `assets/raw/`，运行一条命令即可完成增量去背/压缩并纳入程序。

**非目标（明确不做）**

- 不做多只桌宠、不做宠物商店/多角色切换。
- 不做联网功能（不下载素材、不上传数据、不做云同步）。
- 不做声音素材采集与播放（整点报时默认仅气泡提示，不播放音频）。
- 不做像素级真穿透（见 §9.3 说明与理由）。
- 不做 macOS/Linux 适配（仅 Windows）。
- 不做自动图像语义分类（不训练模型；分类由缩略图 + 人工方式完成）。

## 4. 双轨制视觉策略

**轨道 A — 真透明桌宠**（用于去背干净的素材，判定为「易」级别的图）

去背成功的 GIF 直接在透明无边框窗口里播放，噜噜本体浮在桌面上，可以自由漫游、贴边隐藏。

**轨道 B — 圆角贴纸卡片**（用于去背不干净 / 保留原图的素材）

不强行抠图，而是把原图整体显示为一张卡片：圆角裁切 + 1px 浅色描边 + 24px 柔和投影。视觉上像一张贴纸贴在桌面，观感统一，不需要透明。

**使用规则**

| 场景 | 轨道 | 理由 |
|---|---|---|
| 桌宠主体（待机/走动/睡觉等自由漫游状态） | A（有 A 类素材时）；否则 B | 主体要贴桌面，必须有真透明 |
| 提醒弹窗中的动画（喝水/吃饭/久坐） | B 优先 | 弹窗本身有背板，卡片形态更自然 |
| 表情/心情面板、点一下的反应动画 | A 与 B 都可 | 尺寸小，卡片不突兀 |
| 设置面板里的「我的噜噜」预览墙 | B | 便于统一展示 |

程序启动时按「分类 → A 类素材清单」的顺序挑选主体素材；若某分类一个 A 类素材都没有，该分类降级用 B。这个判定在 `catalog.py` 里做，行为层无感知。

## 5. GIF 预处理流水线（tools_cli/prepare.py）

### 5.1 去背算法

对每个 GIF 逐帧处理，流程：

1. 取该帧 RGBA 像素。
2. **背景色采样**：取四角各 5×5 区域的中位数颜色作为背景色候选；若四角颜色不一致（最大通道差 > 32），再看四边中点，取出现次数最多的候选作为背景色。
3. **边缘 flood-fill**：从四条边界上所有与背景色接近（通道差 ≤ 容差 `tol`，默认 32）的像素出发，做 BFS/扫描线填充，只有与背景色相近的连通区域会被清掉，噜噜内部的同色区域不会被误伤。
4. **可去背程度评分** `ratio = 被清除像素数 / 总像素数`，同时计算「边界被清除比例」`edge_ratio`。
5. **分级判定**：
   - `edge_ratio >= 0.70` 且 `0.05 <= ratio <= 0.75` → **易**（A 类，进轨道 A）
   - `edge_ratio >= 0.35` → **中**（B 类，保留原图做卡片）
   - 其他 → **难**（B 类）
   - 另外，若原图本身已有透明通道 → 直接判 A 类，跳过抠图。
6. **边缘处理（关键）**：GIF 透明是 1-bit，去背后边缘必留白边。做法是把 alpha 掩膜向内收缩 1px（腐蚀），再输出；这样镂空区域比实际稍小，视觉上不会出现白色描边。

### 5.2 尺寸、帧率与压缩

| 项 | 规则 | 理由 |
|---|---|---|
| 尺寸 | 长边缩放到不超过 320px（保持比例，Lanczos） | 桌宠实际显示 120–200px，320px 足够，兼顾高分屏 |
| 帧率 | 高于 12 fps 的降到 12 fps（等比抽帧） | 桌面小尺寸下 12fps 观感足够，体积可显著下降 |
| 颜色 | 量化到 128 色 | 体积下降明显，卡通素材肉眼几乎无差 |
| 目标体积 | 单文件 ≤ 500 KB，全量 ≤ 80 MB | 保证加载与启动速度 |
| 透明 | `disposal=2`，透明色索引保留 | 逐帧独立，避免残影 |

压缩前后会输出一份报告（文件数、总体积、A/B 分类数量、体积最大的 10 个文件），便于人工核查。

### 5.3 缩略图与人工分类

- `tools_cli/contact_sheet.py` 扫描 `processed/`，每 60 张拼成一张接触表图片（网格 10 列 × 6 行，每格 150×150，格下标注文件名），输出到 `assets/contact_sheet_01.png`、`_02.png`…。
- 用户看接触表，把文件名填进 `assets/categories.json` 的对应分类。
- `categories.json` 结构：

```json
{
  "version": 2,
  "categories": {
    "idle":  { "files": ["lulu_003.gif", "lulu_010.gif"], "track": "auto" },
    "walk":  { "files": ["lulu_021.gif"], "track": "auto" },
    "sleep": { "files": [], "track": "auto" },
    "eat":   { "files": ["lulu_088.gif"], "track": "auto" },
    "drink": { "files": [], "track": "auto" },
    "happy": { "files": [], "track": "auto" },
    "angry": { "files": [], "track": "auto" },
    "unassigned": { "files": ["lulu_500.gif"], "track": "auto" }
  }
}
```

  - `track` 由 `prepare.py` 写入：`"transparent"`（A 类）或 `"card"`（B 类）。人工分类时不用关心。
  - 兜底：某分类为空时，行为层回退到 `idle`；`idle` 为空则回退到 `unassigned`；再为空则回退到 `processed/` 目录任意文件。程序不会因为分类没填完而崩溃或空白。
  - 空分类会给用户一个温和提示（托盘 tooltip + 设置面板里的提示条），但不阻塞运行。

### 5.4 增量素材（后续替换/追加）——必须支持

- 用户把新的一批 GIF 直接丢进 `assets/raw/`。
- 运行 `python tools_cli/prepare.py --incremental`：
  1. 计算 `raw/` 下每个文件的 MD5，与 `assets/.index.json` 中已处理的指纹对比（同时按内容哈希去重，跳过重复素材）。
  2. 只处理新文件。
  3. 文件名沿用 `lulu_NNN.gif` 规则，编号从 `processed/` 现有最大编号 +1 继续，不覆盖旧文件。
  4. 新文件全部先归入 `categories.json` 的 `unassigned`，并提示用户重新生成接触表并分类。
  5. 更新 `.index.json`。
- `prepare.py` 不带参数时处理 `raw/` 下全部未处理文件（等价于增量），带 `--rebuild` 才清空重建 `processed/`。
- **一次替换**：如果用户想用新素材整体换掉旧的，用 `--rebuild`；程序侧不需要改代码。

## 6. 行为状态机（pet/behavior.py）

**状态集合**

| 状态 | 含义 | 素材来源 | 进入方式 |
|---|---|---|---|
| `IDLE` | 站着发呆/轻微动作 | `idle` | 默认状态，事件结束后回到这里 |
| `WANDER` | 在桌面上缓慢走动 | `walk` | IDLE 随机触发 |
| `SLEEP` | 睡觉 | `sleep` | 长时间无操作（默认 15 分钟） |
| `EAT` | 吃东西 | `eat` | 12:00 / 18:30 吃饭提醒 |
| `DRINK` | 喝水 | `drink` | 喝水提醒（无 `drink` 素材时用 `eat` 兜底或仅弹气泡） |
| `HAPPY` | 开心/被摸 | `happy` | 被点击、番茄钟完成 |
| `ANGRY` | 生气 | `angry` | 被连续快速点击（3 秒内 ≥5 次） |
| `DRAGGED` | 被拖拽中 | `idle` 冻结当前帧 | 鼠标按下并移动 |
| `HIDDEN` | 贴边隐藏 | `orange.png` | 拖到屏幕边缘松手 |

**状态优先级**（同时命中时取最高）

```
模块事件驱动（EAT/DRINK/HAPPY） > 用户交互（DRAGGED/HAPPY/ANGRY） > 自动状态（WANDER/SLEEP） > IDLE
```

**转移规则**

- 一个「事件驱动」状态播放一轮 GIF 后自动回到 `IDLE`（默认播放 1 次或最长 8 秒，取先到者）。
- 「自动状态」由一个随机定时器驱动：每次进入 IDLE 后按该分类配置的 `[min_gap, max_gap]` 秒随机取一个间隔，到点后按概率切到 `WANDER` 或 `SLEEP`。
- 用户拖拽优先级最高：拖拽期间冻结动画播放（显示当前帧），松手后回到 `IDLE`，并检测是否触发贴边隐藏。
- 所有状态切换都通过 `play(category)` 请求 `sprite.py` 换图；`sprite.py` 内部有 LRU 缓存（见 §7.3）。

## 7. 渲染与位置（pet/sprite.py、pet/edge_hide.py）

### 7.1 主窗口

- `Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.Tool`（`Qt.Tool` 避免在任务栏出现第二个图标）。
- `WA_TranslucentBackground` 实现真透明；卡片形态用同一个窗口，只是绘制时加圆角背景 + 投影。
- 窗口大小 = 当前 GIF 尺寸（A 类）或 GIF 尺寸 + 投影留白（B 类）。
- 高 DPI：启动时开启 `Qt.AA_EnableHighDpiScaling` 并设置 `QT_AUTO_SCREEN_SCALE_FACTOR`，避免高分屏模糊。
- 多显示器：位置按「光标所在屏幕」的逻辑坐标存储；屏幕拔插后做一次位置合法性校验，越界则回到主屏右下角。

### 7.2 交互

| 操作 | 行为 |
|---|---|
| 左键单击 | 播放 `happy` 动画（1 次） |
| 左键快速连点（3 秒 ≥5 次） | 播放 `angry` 动画 |
| 左键按住拖动 | 移动窗口；松手时判断贴边 |
| 右键 | 弹出菜单（与托盘菜单同源，见 §9.1） |
| 双击 | 打开设置面板 |
| 鼠标悬停 | 显示气泡：当前模块状态摘要（如番茄钟剩余时间），默认开启 |

### 7.3 播放与内存

- 使用 `QMovie` 播放 GIF，`setScaledSize` 缩放到显示尺寸。
- 全局最多保留 3 个 `QMovie` 实例（当前 + 预加载下一个 + 上一个），切换状态时销毁旧的，避免内存堆积。
- 最多同时存在的 GIF 解码缓存 ≤ 3 个 × 320px × 12fps，内存占用可控（预计 < 60 MB）。

### 7.4 贴边隐藏

- 触发：拖动到屏幕左/右边缘 24px 内松手（仅左右两侧；上下不做，避免遮挡任务栏与标题栏）。
- 进入：窗口平滑滑出屏幕外，仅保留 48px 宽的桔子竖条可见（`assets/orange.png`，若素材缺失则代码绘制一个 48×48 的圆润桔子图形作为兜底）。
- 恢复：鼠标移入桔子条区域 → 平滑滑出完整噜噜；鼠标离开噜噜 3 秒 → 重新缩回。
- 状态存入配置，重启后保持贴边状态。

## 8. 实用模块（modules/）

**统一接口**（`modules/base.py`）

```python
class Module:
    name: str            # 唯一标识，配置键
    title: str           # 托盘菜单显示名
    default_enabled: bool

    def enable(self) -> None: ...     # 开启：注册定时器/读取配置
    def disable(self) -> None: ...    # 关闭：停止定时器/清理
    def tick(self, now: datetime) -> None: ...   # 由 1 秒主循环调用，仅当 enabled
    @property
    def enabled(self) -> bool: ...

class ModuleContext:      # 模块可用能力，限制模块越权
    def notify(self, text: str, category: str = "happy", duration_ms: int = 6000) -> None:
        """弹气泡 + 请求行为层播放一轮指定分类动画（不抢占当前用户交互）"""
    def config(self) -> dict: ...
    def save_config(self) -> None: ...
```

模块只能通过 `ctx.notify()` 与外界交互，不直接访问窗口或文件；`tick` 内部必须是无副作用的时间判断（便于测试注入假时钟）。

**五个模块**

| 模块 | 默认 | 行为细节 |
|---|---|---|
| `pomodoro` 番茄钟 | 关 | 默认 25 分钟专注 + 5 分钟休息，可配置；支持托盘「开始/暂停/跳过/重置」；专注结束 → 播放 `happy` + 气泡「专注完成，休息 5 分钟」；休息结束 → 气泡 + 播放 `idle` |
| `health_reminder` 喝水·久坐 | 开 | 两个独立子开关：喝水每 45 分钟、久坐每 60 分钟；到点 → 喝水用 `drink` 分类（无素材则仅气泡）、久坐用 `happy`/`idle` 气泡「起来动一动」；支持「稍后提醒 10 分钟」 |
| `meal_reminder` 吃饭提醒 | 开 | 每天 12:00 与 18:30；到点 → 播放 `eat` 分类动画 + 气泡「该吃饭啦」；错过（程序未运行）不补发；时间点可配置 |
| `hourly_chime` 整点报时 | 关 | 每个整点 → 气泡显示「现在是 14:00」+ 播放一轮 `idle`；**不播放声音**（非目标） |
| `sysmonitor` 系统状态监控 | 关 | 每 3 秒采样 CPU / 内存 / 磁盘占用（psutil）；托盘 tooltip 常驻显示；hover 气泡显示详情；超过阈值（CPU 85% / 内存 90%）→ 播放 `angry` + 气泡提示，同一指标 10 分钟内不重复告警 |

- 所有模块默认开关状态可配置，首次运行按上表默认值。
- 托盘菜单中每个模块一行勾选项，勾选即调用 `enable()/disable()`，立即生效并写回配置。
- 设置面板提供每个模块的详细参数（间隔、时间点、时长、阈值）。

### 9.1 系统托盘（pet/tray.py）

- `QSystemTrayIcon` + 右键菜单（与桌宠右键菜单共用同一套 `QMenu` 构造逻辑，避免两处不一致）。

            吃饭提醒（勾选）

            系统监控（勾选）

开机自启               （勾选）

- 菜单中的「喝水提醒 / 久坐提醒」是同一个 `health_reminder` 模块的两个子开关（见 §8），因此菜单里出现 6 行开关，对应 5 个模块。

### 9.2 开机自启（pet/autostart.py）

- 通过注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 写入/删除 `LuluPet` 项。
- 脚本模式下写入 `pythonw.exe "…\main.py"`；打包模式下写入 exe 路径。
- 只写当前用户，不需要管理员权限；失败时（无权限）托盘弹一次气泡说明，不抛异常。

### 9.3 鼠标穿透 —— 采用双模式切换（明确决策）

- **交互模式（默认）**：窗口正常接收鼠标事件，可拖拽、点击、右键。
- **穿透模式**：给主窗口加 `Qt.WindowTransparentForInput`，所有点击穿透到下层窗口；此时只能通过托盘菜单切回交互模式。
- 切换后菜单项文案与勾选状态同步，并在托盘 tooltip 上显示当前模式。

**为什么不做像素级真穿透**：Windows 上需要处理 `WM_NCHITTEST` 并返回 `HTTRANSPARENT`，PyQt5 需借助 `nativeEvent` 与 `ctypes` 手写窗口过程，跨 Windows 版本与高 DPI 场景风险高，且与"拖拽移动"这一必需交互互相冲突（真穿透窗口收不到拖拽事件）。双模式在实现成本与可用性之间是最优解：需要操作噜噜时用交互模式，需要专心工作时切穿透模式。此决策已与用户确认。

### 9.4 始终置顶

`Qt.WindowStaysOnTopHint`。若被全屏应用（如游戏、演示）遮挡属预期行为，不额外处理。

### 9.5 跟随与例外

- 噜噜不抢焦点：所有窗口设置 `Qt.WA_ShowWithoutActivating`，点击噜噜不会让当前正在打字的窗口失焦。
- 全屏应用运行时（检测到前台窗口全屏）自动隐藏噜噜与气泡，退出全屏后恢复；此行为可配置，默认开启。

## 11. 打包与分发（tools_cli/build.py）

- PyInstaller，`--noconsole --onedir`（不用 `--onefile`，避免每次启动解压导致启动慢）。
- **素材外置**：`assets/` 不打进 exe，作为 exe 同级目录分发。理由：329 MB 原始素材 / ~80 MB 处理后素材进 exe 会使体积与启动时间不可接受，同时外置便于用户后续替换素材。
- 首次运行若发现 `assets/processed/` 为空：弹出引导气泡，提示"请把 GIF 放进 assets/raw/ 并运行 prepare"，程序以「仅卡片形态 + 提示」方式降级运行，不崩溃。
- 产物：`dist/lulu_pet/lulu_pet.exe` + `assets/` + `config.json`。
- `build.py` 负责：检查 PyInstaller → 清理旧产物 → 执行打包 → 把 `assets/` 与默认 `config.json` 复制到 `dist/lulu_pet/` → 打印最终体积。
- 运行时依赖：PyQt5、Pillow、psutil。仅开发期额外需要 pytest；`numpy` 不引入（Pillow 自带像素运算足够，减少打包体积）。

## 12. 错误处理

| 场景 | 处理 |
|---|---|
| `assets/processed/` 为空或不存在 | 程序正常启动，显示兜底卡片（代码绘制的噜噜占位图 + 文字提示），托盘 tooltip 提示需准备素材 |
| `categories.json` 缺失/损坏/分类为空 | 用内置默认结构；空分类回退到 `idle` → `unassigned` → 目录任意文件；不崩溃 |
| 单个 GIF 解码失败 | 跳过该文件并从当前会话的候选列表移除，日志记录，继续用其他素材 |
| 所有候选都失败 | 显示兜底占位图并提示用户重新运行 `prepare.py` |
| 配置写入失败 | 内存中生效，托盘气泡提示一次 |
| 开机自启注册表写入失败 | 气泡提示一次，不重试、不抛异常 |
| `prepare.py` 遇到损坏的 GIF | 跳过并计入报告，不中断整批处理 |
| 屏幕分辨率/显示器变化 | 启动与 `screenAdded/Removed` 时校验窗口位置，越界则回到主屏右下角 |

日志：`logs/pet.log`（单文件，超过 2 MB 轮转一次，保留 1 份备份）。

## 15. 风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| 去背成功率低（实测易去背仅 15%） | 真透明桌宠素材可能不足 | 分级阈值可调（`--tol` / `--edge-min`）；接受"部分素材只能做卡片"；后续新增素材若底色干净则自动进 A 类 |
| GIF 1-bit 透明导致边缘白边 | 视觉质量 | 掩膜收缩 1px；显示端 Lanczos 缩放 |
| 506 张全量处理耗时 | 首次准备体验 | 多进程并行处理；增量模式日常只处理新图 |
| 常驻内存与 CPU | 长期后台占用 | `QMovie` 只保留 3 个实例；处理后的图 ≤ 320px / 12fps；系统监控 3 秒一次采样（不用更密集） |
| 打包后杀软误报 | 分发受阻 | 仅用 PyInstaller 官方产物，不混淆；如遇误报在文档中说明需加白名单 |
| 高 DPI 下画面模糊/位置错位 | 视觉与交互 | 开启 DPI 感知；位置用逻辑坐标存；显示器变化时校验 |

**已定默认值（实现按此执行，无需再决策）**

1. 桔子素材：`prepare.py` 先从现有素材中尝试提取一张干净的桔子（四角纯色底 + 主体为橙色圆形）；提取失败则用 `QPainter` 绘制 48×48 圆润橙色椭圆 + 一片叶子作为 `orange.png` 兜底。
2. 卡片样式：圆角 16px、描边 `#00000014`（1px）、投影 24px 模糊、投影色 `#00000040`。
